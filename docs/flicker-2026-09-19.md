# Composited photo-disappearance capture

A dedicated GPU-backed Weston output now supplies actual composited frames.
The main photo disappears to the dark background during a drag while the menu
strip and filmstrip remain visible. Its VKD3D overlay disappears too. This was
visually confirmed in the captured frames, including a repeat with the photo
already zoomed and no metadata action. It is not a hidden X11-window readback.

In the warmed repeat, 59 of 139 samples taken during the ten-second drag showed
the low-luminance blank-photo state. This is a **sample count**, not FPS or a
precise duration: capture readback itself slowed down under load. A corrected
Space zoom also produced one sampled blank transition. X11 structure-event
observation across a later zoom/drag saw no map, unmap or resize notifications
from the 37 watched windows. That narrows the investigation toward rendered
content and presentation; it does not establish a root cause.

Disabling `dxgi.enableDummyCompositionSwapchain` in a separate candidate launch
still reproduced blank frames (63 across the full 280-frame recording).
The runtime log confirmed the option was false. The workaround therefore was
not sufficient to explain or fix this reproduction. It was not changed in the
production configuration. Normal direct swapchain resize messages appeared
when the test window was resized, before the scored gesture.

[Numeric recordings](measurements/20260919-flicker/) include capture completion
times and input boundaries. Photographs/screenshots stay private under the
application data directory, `measurements/composited/`. Luminance thresholds
here describe this particular test photo and are not a general blank detector.

## Correcting the input script

The helpers incorrectly used `Z` for zoom, a Lightroom Classic shortcut. For
this Lightroom Desktop build, [Adobe documents Space for zoom and Z for a pick
flag](https://helpx.adobe.com/nz/lightroom/desktop/using/keyboard-shortcuts.html).
Both helpers now send Space. Any older `zoom` action log is not evidence of a
zoom operation.

The isolated test photo's accidental pick operation was reversed through its
specific **Undo Flag as Pick** menu item. A subsequent composited screenshot
showed **Redo Flag as Pick** and a disabled Undo entry, confirming the reversal
in that session. The repeat warm-pan recording happened after the reversal.
No direct input was sent to the production window.

## Capture tool

After staging Weston, build `diagnostics/build-composited-capture.sh` and start
`diagnostics/headless-session.py start --capture`. This enables Weston's capture
authorization only on the dedicated `lightroom-test` compositor; the normal
Hyprland session is untouched. The [Weston manual](https://cgit.freedesktop.org/wayland/weston/tree/man/weston.man)
describes this diagnostic authorization.

With an existing empty output directory:

```sh
WAYLAND_DISPLAY=lightroom-test "$HOME/.local/share/omarchy-lightroom-cc/tools/composited-capture" OUTPUT_DIRECTORY 280 20 > OUTPUT_DIRECTORY/frames.csv
```

The client connects explicitly to `lightroom-test`, refuses other display
settings, saves quarter-resolution PNGs with exclusive creation, and measures
capture latency. It samples a central region's luminance. Full frame readback
can perturb rendering substantially: never report these screenshots as an FPS
benchmark. Keep capture separate from performance comparisons.
