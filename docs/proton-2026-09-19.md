# Custom Proton migration, 19 September 2026

The running session uses **lightroom-omarchy-proton 11.7-1**, based on GE-Proton11-7,
through UMU 1.4.4 and Steam Linux Runtime 4. Proton includes Wine; the app no
longer runs under the standalone Wine Staging runner. The previous signed-in
prefix is preserved separately for rollback.

Source and component hashes are published in the
[Proton fork](https://github.com/LamplighterPaul/lightroom-omarchy-proton).
This is the complete GE distribution with selected Wine components rebuilt
in a digest-pinned SDK, not a rebuild of every third-party dependency.

## Verified changes

- The original Windows username is explicitly preserved during migration.
  A disposable DPAPI encrypted-string round trip failed under stock Proton's
  `steamuser` identity and passed with the username patch. No Adobe secrets
  are read or published by that test. The migrated library loads without
  missing-access-token errors. Fresh sign-in under this build is not verified.
- A startup access violation dereferenced the missing `INetFwRules::_NewEnum`
  result. A Wine 11.10 backport supplies the empty enumerator. A COM probe checks
  enumeration, reset and clone. The app subsequently opened its library/photo
  view and the operator reported stability. This does not establish long-term
  crash freedom or change Linux firewall rules.
- Monitor scaling follows the target Omarchy monitor; the operator confirms 2x.
- The Windows File/Edit menu strip uses Tokyo Night palette colours, centered
  entries and increased spacing. Adobe's own interface remains unchanged.
  Tahoma registrations are restored for the migrated prefix's DirectWrite layouts.
- GUI launches target workspace 10 silently. A dedicated compatibility app ID
  scopes the helper-window rule as well. It is metadata, not a Steam dependency.
- A daily user timer checks upstream GE releases; upgrades are not automatically
  installed. New candidates require build and interaction validation.

## Performance and remaining work

The operator still reports dark flicker and choppy photo panning/menus.
No 60 or 120 FPS result has been demonstrated. A five-second idle measurement
recorded 10.84% of one CPU core and 3291.9 MiB PSS across the prefix. GPU resident
allocations were approximately 3045 MiB and overlap CPU/shared memory; do not
sum them. This was not an interaction benchmark or an A/B comparison.

Optional MangoHud 0.8.4 provides presentation FPS, frame-time graph and local CSV
recording. The resource recorder provides per-process CPU/PSS and per-DRM-client
engine activity with timestamps. Instrumentation and repeatable actual panning
are required before claiming a performance improvement. See
[performance-loop.md](performance-loop.md).

The Direct2D colour-management effect still uses an experimental pass-through.
Correct colour transforms and the cause of the dark flicker remain unresolved.
A separate arc-geometry candidate compiled, but is not installed in the stable
baseline. UI font matching is deferred in favour of performance work.

Validation at publication: 19 launcher tests pass; credential and firewall COM
probes pass; cloud library and themed menus visually inspected; user reports
stability and persistent stutter. No private photos, prefixes or raw Adobe logs
are included in either repository.

## Subsequent runtime validation

The optional MangoHud overlay loads in Lightroom under UMU and exposes separate
VKD3D photo and DXVK UI presentation paths. Its host CPU/RAM totals are not the
prefix CPU/PSS values from the resource recorder. Hidden-window screenshots can
return black GPU surfaces; those samples do not establish the visible flicker.

Closing 11.7-1 exposed an unimplemented UI Automation shutdown export. Version
11.7-2 backports Wine 11.10's non-aborting stub, and its API-set probe passes.
The next shutdown exposed an ntdll threadpool assertion, so a clean restart is
still not validated. This updates the earlier operator stability observation.
The live library/photo view continues to load. The helper-window ID is now an
alphanumeric UMU ID and its actual X11 class is verified on workspace 10.
